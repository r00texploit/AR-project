# المعمارية والبيانات

## نظرة معمارية

يعتمد التطبيق على مشاهد Unity منفصلة لكل جزء من التجربة، مع كائنات إدارة مستمرة مثل `DataManager` و`SceneLoader`.

```text
MainMenu
  ينشئ DataManager و SceneLoader
  يختار الطالب الدرس أو الاختبار

ARLesson
  يشغل ARSession و XR Origin
  يضع نموذج الدرس في البيئة
  يمرر أحداث الوضع والتحريك إلى LessonManager

Quiz
  يحمل أسئلة الدرس من Resources
  يحسب الدرجة
  يحفظ النتيجة محليًا

TeacherDashboard
  يقرأ النتائج المخزنة
  يعرضها ويصفيها حسب الدرس
```

## طبقة AR

مجلد:

```text
Assets/Scripts/AR/
```

| الملف | الدور |
|---|---|
| `ARSessionController.cs` | إدارة جاهزية AR، صلاحية الكاميرا، ورسائل الحالة |
| `ARPlacementManager.cs` | استخدام Raycast على أسطح AR لوضع نموذج الدرس |
| `ARObjectManipulator.cs` | تحريك وتدوير وتكبير/تصغير النموذج باللمس |

يعتمد وضع المجسم على اكتشاف الأسطح ثم لمس الشاشة. بعد وضع المجسم، يتم إخفاء مرئيات الأسطح لتقليل التشويش.

## طبقة الدروس

مجلد:

```text
Assets/Scripts/Lessons/
```

| الملف | الدور |
|---|---|
| `LessonBase.cs` | صنف أساسي مشترك للدروس |
| `LessonManager.cs` | اختيار الدرس الحالي وربطه بنظام AR |
| `TriangleLessonController.cs` | منطق درس المثلث |
| `CubeLessonController.cs` | منطق درس المكعب |
| `PhysicsLessonController.cs` | منطق درس الفيزياء |

يستخدم `LessonManager.SelectedLesson` لاختيار الدرس قبل تحميل مشهد AR. بعد ذلك يفعّل الدرس المناسب ويعطيه إلى `ARPlacementManager` ليتم وضعه في البيئة.

## طبقة الاختبارات

مجلد:

```text
Assets/Scripts/Quiz/
```

| الملف | الدور |
|---|---|
| `QuizManager.cs` | تحميل الأسئلة، خلطها، حساب الدرجة، وحفظ النتيجة |
| `QuizUIController.cs` | تحديث واجهة الاختبار والاستجابة لاختيارات الطالب |

ملفات الأسئلة موجودة في:

```text
Assets/Resources/QuizData/
```

الأسماء المعتمدة:

```text
triangle_quiz.json
physics_quiz.json
cube_quiz.json
```

شكل البيانات العام:

```json
{
  "questions": [
    {
      "questionId": "q1",
      "lessonId": "triangle",
      "questionText": "نص السؤال",
      "options": ["خيار 1", "خيار 2", "خيار 3", "خيار 4"],
      "correctIndex": 0,
      "explanation": "شرح الإجابة"
    }
  ]
}
```

## نماذج البيانات

أهم النماذج:

| النموذج | الاستخدام |
|---|---|
| `StudentProfile` | بيانات الطالب: الاسم، الصف، الفصل، والمعرّف |
| `QuizQuestion` | سؤال اختبار واحد |
| `QuizResult` | نتيجة محاولة اختبار |
| `QuizResultList` | غلاف لقائمة النتائج لأن `JsonUtility` لا يدعم مصفوفة جذرية مباشرة |
| `ReportExport` | معلومات تقرير PDF بعد إنشائه |

## التخزين المحلي

يستخدم التطبيق `PlayerPrefs` للتخزين المحلي. المفاتيح المهمة:

| المفتاح | المحتوى |
|---|---|
| `student_profile_v1` | ملف الطالب الحالي |
| `quiz_results_v2` | نتائج الاختبارات الحالية |
| `quiz_results_v1` | مفتاح قديم يتم ترحيله إذا وجدت بيانات سابقة |
| `ar_enabled` | حالة تفعيل وضع AR |

كل البيانات محلية على الجهاز، ولا يحتاج التطبيق إلى خادم خارجي في هذا الإصدار.

## التقارير

عند طلب تصدير تقرير، يستخدم `ReportGenerator` بيانات الطالب ونتائج الاختبارات لإنشاء ملف PDF داخل:

```text
Application.persistentDataPath/Reports/
```

ثم يمكن لـ `AndroidShareService` مشاركة الملف عبر نية Android من نوع:

```text
android.intent.action.SEND
```

## تدفق نتيجة الاختبار

```text
QuizManager.LoadQuiz()
  يحمّل ملف JSON من Resources/QuizData
  يخلط الأسئلة
  يعرض السؤال الحالي

QuizManager.CheckAnswer()
  يقارن الاختيار مع correctIndex
  يحدث الدرجة
  يرسل حدثًا إلى الواجهة

QuizManager.FinishQuiz()
  ينشئ QuizResult
  يستدعي DataManager.SaveQuizResult()

LocalDataStore.SaveResult()
  يقرأ القائمة الحالية
  يضيف النتيجة
  يحفظ JSON في PlayerPrefs
```

## تدفق درس AR

```text
MainMenuController
  يحدد نوع الدرس
  ينتقل إلى ARLesson

LessonManager
  يقرأ الدرس المحدد
  يهيئ LessonController المناسب
  يمرر كائن الدرس إلى ARPlacementManager

ARPlacementManager
  ينتظر لمس سطح مكتشف
  يضع النموذج
  يطلق حدث OnObjectPlaced

LessonController
  يستقبل Pose
  يبدأ تفاعل الدرس
```

## إضافة درس جديد

لإضافة درس جديد عادة تحتاج إلى:

1. إنشاء Controller جديد يرث من `LessonBase`.
2. إضافة Prefab أو نموذج للدرس.
3. تحديث `LessonManager` لإضافة نوع الدرس الجديد.
4. تحديث القائمة الرئيسية لإظهار الدرس.
5. إضافة ملف اختبار جديد داخل `Assets/Resources/QuizData/`.
6. تحديث لوحة المعلم إذا احتجت فلترة أو اسمًا جديدًا للدرس.

## إضافة أسئلة جديدة

1. افتح ملف JSON المناسب في `Assets/Resources/QuizData/`.
2. أضف سؤالًا جديدًا داخل مصفوفة `questions`.
3. تأكد أن `options` تحتوي على أربعة خيارات.
4. تأكد أن `correctIndex` رقم بين `0` و`3`.
5. شغّل مشهد `Quiz.unity` واختبر السؤال.

## ملاحظات مهمة للمطورين

- ابدأ دائمًا من `MainMenu.unity` عند اختبار تجربة كاملة، لأن بعض الكائنات المستمرة تنشأ هناك.
- لا تغيّر أسماء ملفات الاختبارات دون تحديث منطق التحميل في `QuizManager`.
- عند إضافة نماذج بيانات جديدة مهمة لنسخة IL2CPP، راجع `Assets/link.xml`.
- قبل بناء APK، تأكد من تشغيل إعداد المشاهد أو الاعتماد على `BuildPreprocessor` أثناء البناء.
